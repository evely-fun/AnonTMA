# Deployment

## Live deployment

Everything runs on Render in the `frankfurt` region, deployed from the
`claude/affectionate-cray-idu7f1` branch with auto deploy enabled.

| Piece | Name | URL |
| --- | --- | --- |
| Mini app | `anontma` (static site) | https://anontma.onrender.com |
| API and WebSocket | `anontma-api` (web service) | https://anontma-api.onrender.com |
| Database | `anontma-db` (Postgres 16, free) | internal only |
| Live state | `anontma-cache` (Key Value, free) | internal only |

The bot is `@AnteikuAnonBot` and its webhook is registered automatically on
boot at `/telegram/webhook`.

Free plan limits worth knowing:

- the web service sleeps after 15 minutes of inactivity, so the first request
  after a quiet period takes about a minute and open sockets drop
- the free Postgres instance expires 30 days after creation, upgrade it before
  then to keep the data
- the free Key Value store holds 25 MB, which covers presence, matchmaking and
  live game state at this scale

Secrets live only in the Render environment, never in this repository.

## Reproducing the deployment from scratch

The blueprint in `render.yaml` provisions the same stack on paid plans, where
the database and cache are wired automatically. The steps below cover a manual
setup, including the Cloudflare Pages variant if you prefer the mini app on a
CDN closer to your users.

## 1. What you need to provide

| Value | Where to get it | Example |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | [@BotFather](https://t.me/BotFather) → `/newbot` | `8012345678:AAE...` |
| `TELEGRAM_BOT_USERNAME` | the bot username without `@` | `anon_voice_bot` |
| Render account | render.com, connect this GitHub repo | — |
| Cloudflare account | dash.cloudflare.com → Workers & Pages | — |

Everything else is generated or derived.

## 2. Environment variables

### Backend (Render web service)

| Key | Value | Notes |
| --- | --- | --- |
| `ENVIRONMENT` | `production` | disables docs and the dev login route |
| `TELEGRAM_BOT_TOKEN` | from BotFather | **you provide** |
| `TELEGRAM_BOT_USERNAME` | e.g. `anon_voice_bot` | **you provide**, no `@` |
| `TELEGRAM_WEBHOOK_SECRET` | auto generated by the blueprint | 32+ random chars |
| `JWT_SECRET` | auto generated by the blueprint | 64 hex chars |
| `PAYLOAD_ENCRYPTION_KEY` | auto generated by the blueprint | any long random string |
| `DATABASE_URL` | wired from `anontma-db` | `postgresql://...` |
| `REDIS_URL` | wired from `anontma-cache` | `redis://...` |
| `PUBLIC_API_URL` | your Render URL | `https://anontma-api.onrender.com` |
| `PUBLIC_WEB_URL` | your Pages URL | `https://anontma.pages.dev` |
| `CORS_ORIGINS` | same as `PUBLIC_WEB_URL`, comma separated | `https://anontma.pages.dev` |
| `TURN_URLS` | optional, comma separated | `turn:turn.example.com:3478` |
| `TURN_USERNAME` / `TURN_CREDENTIAL` | optional | for the TURN server |

If you need to generate secrets yourself:

```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

### Frontend (Cloudflare Pages)

| Key | Value |
| --- | --- |
| `VITE_API_URL` | `https://anontma-api.onrender.com` |
| `NODE_VERSION` | `22` |

`VITE_API_URL` is read at build time, so changing it needs a redeploy.

## 3. Steps

1. **Render.** New → Blueprint → pick this repo. The blueprint creates
   `anontma-api`, `anontma-db` and `anontma-cache`, and generates the secrets.
   Fill in `TELEGRAM_BOT_TOKEN` and `TELEGRAM_BOT_USERNAME` when prompted; leave
   the URL variables blank for now. Deploy, then copy the service URL.
2. **Cloudflare Pages.** Workers & Pages → Create → Pages → connect the repo.
   - Root directory: `frontend`
   - Build command: `npm run build`
   - Output directory: `dist`
   - Variables: `VITE_API_URL` = the Render URL, `NODE_VERSION` = `22`
   Deploy and copy the `*.pages.dev` URL.
3. **Back to Render.** Set `PUBLIC_API_URL`, `PUBLIC_WEB_URL` and `CORS_ORIGINS`
   to the two URLs, then redeploy. On boot the service registers the Telegram
   webhook itself at `PUBLIC_API_URL/telegram/webhook`.
4. **BotFather.** Send `/mybots` → your bot → Bot Settings:
   - *Menu Button* → *Configure menu button* → the Pages URL, label `Open Anon`
   - *Configure Mini App* → *Enable* → the Pages URL
   This makes `https://t.me/<bot>/app` work, which is what invite links use.
5. **Check.** Open the bot, press start, tap the button. `/health` on the API
   should answer `{"status":"ok"}` and the home screen should show a live online
   counter.

## 4. Voice behind strict NAT

STUN alone connects most mobile networks. Some carrier NATs need a TURN relay.
Cheapest reliable options: Cloudflare Calls TURN, Metered, or coturn on a small
VPS. Set `TURN_URLS`, `TURN_USERNAME`, `TURN_CREDENTIAL` and redeploy — the
client picks them up from `/api/v1/config/ice` with no code change.

## 5. Plan notes

- Render's free web service sleeps after inactivity, which drops WebSockets and
  makes matchmaking feel broken. The blueprint uses `starter` for that reason.
- The Key Value store must keep `maxmemory-policy` at `noeviction`, since
  presence, matchmaking and live game state live there.
- Postgres `basic-256mb` is enough to start; game state is only persisted when a
  match finishes.

## 6. Scaling

The API is stateless. Every cross-process message goes through Redis pub/sub, so
raising the instance count works without changes. Live state is keyed in Redis
(`presence:*`, `matchmaking:*`, `dialog:*`, `room:*`, `game:*`) and games are
guarded by per-game locks, so two workers never advance the same match.
